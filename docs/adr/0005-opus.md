# ADR 0005: Use Opus for V1 network audio

## Status
Accepted for V1 wire interoperability; encoder settings, Opus implementation, transport, and provider choices remain provisional.

## Context
Relay needs a low-delay speech-and-music codec with a standardized RTP mapping, loss-resilience controls, and a useful bitrate range. Opus was designed for interactive speech and music across a broad bitrate range, and specifies packet-loss resilience and FEC controls ([RFC 6716 abstract, §§2.1.6–2.1.7](https://www.rfc-editor.org/rfc/rfc6716.html#section-2.1.6); [RFC 7587 §§3.3, 4](https://www.rfc-editor.org/rfc/rfc7587.html#section-3.3)). Codec plurality in V1 would multiply negotiation, testing, and operational complexity.

## Decision
Require Opus for V1 network audio and negotiate it through the WebRTC-compatible media contract. Start with a small, documented profile of packet durations, channel counts, bitrate bounds, and resilience controls, then tune from measured results. Keep the encoder/decoder behind a core interface; do not bind the architecture to a particular Opus library or transport provider. Truce remains a separate, provisional plugin-shell choice.

## Consequences
- V1 gets one standardized RTP payload format and one codec test matrix.
- Codec configuration still requires workload-specific measurement.
- Transcoding should not be needed between conforming V1 peers.
- Licensing, packaging, SIMD, and platform behavior must be validated for the selected implementation.

## Validation gates
- Independent peers exchange negotiated Opus without transcoding.
- Objective quality, latency, CPU, and loss-recovery tests meet published V1 thresholds on target devices.
- Malformed-input, fuzz, and long-duration decode tests pass.
- At least two viable implementation paths are documented before making any library or provider permanent.
